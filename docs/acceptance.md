# MVP 验收清单

更新日期：2026-09-21。阶段 3 浏览器缺口已补，阶段 4 修改及阶段 5 单图交付实现已验证。88+10 项自动测试通过；单图流程浏览器证据见 [阶段 5 验收](stage5-validation.md)。下方阶段 1～4 记录为历史，不覆盖新规则。

## 1. 核心业务验收

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| B01 | 创建订单，填写客户备注 | 生成唯一订单编号，可重新打开详情 |
| B02 | 上传主照片、辅助图、可选参考图 | 当前素材合计最多 4 张，主照片恰好一张才能生成 |
| B03 | 选择发型、眼镜、服装来源 | 参数可保存，缺失来源不能提交 |
| B04 | 首次生成 | 一个目标位置，成功后 1 张直接成为当前交付图 |
| B05 | 修改当前交付图 | 保存基础图片和指令，成功自动替换当前图，失败保留原图 |
| B06 | 连续发起多轮人工修改 | 每次 1 张，轮次递增，无系统硬上限，不自动续改 |
| B07 | 查看版本记录 | 可追溯订单、任务、输入、提示词及基础版本 |
| B08 | 切换交付版本 | 旧版保留，可切回，每单仅一个当前交付图 |
| B09 | 导出交付 | 当前单张原图，命名包含订单编号，不串单 |
| B10 | 完成和关闭 | 满足条件才允许进入终态；关闭不删除文件 |

## 2. 输入与边界验收

- [x] 草稿可暂存空素材，空素材或无主照片不能调用模型。
- [x] 第 5 张当前输入被阻止，两个并发上传也无法绕过上限。
- [x] 主照片切换后仍唯一，参考图最多一张。
- [x] 移出当前素材的图片保留文件；受影响的当前参数清空，历史任务仍按原快照读取文件。
- [x] 修改基础图加附加图片最多 4 张，不会自动附加所有原素材。
- [x] 风格示例若被明确传入，计入总数；不会被后台隐藏追加。
- [x] 其他订单的图片 ID、未知 ID、已作废基础图均被拒绝。
- [x] 空白修改指令、重复输入图片、无效来源参数均被拒绝。
- [x] 非图片、损坏图片、超过当前配置的文件大小或像素限制会给出可理解错误。
- [x] 文件名包含中文或特殊字符不影响保存，不能通过文件名访问存储目录之外的位置。

## 3. 任务、幂等和恢复验收

- [x] 相同幂等键和相同请求返回同一任务组，不增加远端调用。
- [x] 同一键配不同请求返回冲突；同订单有未结束任务时不能新增任务组。
- [x] 历史双图任务一张成功一张失败时保留成功图，API 状态为部分失败，仅补生成失败位置（阶段 4 已补浏览器验收）。
- [x] 修改失败补生成不新增业务修改轮次，但增加实际调用尝试记录。
- [x] 查询接口暂时不可用时退避重试，不判定远端必然失败。
- [x] 提交超时且无远端 ID 时进入结果不明状态，不自动重复生成。
- [x] 结果不明有核对 API 和前端入口，API 和三种核对表单浏览器交互均已验证。
- [x] 远端成功但下载失败时仅补下载，不重新生成。
- [x] 图片下载不完整或无法解码时不标记本地成功。
- [x] Worker 重启后，有远端 ID 的任务继续查询；已落盘结果不重复入库。
- [x] 文件已写入而数据库未提交时复用同摘要文件；不同内容拒绝覆盖。
- [x] 日志和 API 响应不包含密钥或完整 Base64 素材。

## 4. 数据和界面验收

- [x] 历史请求快照不会因调整订单当前参数而变化。
- [x] 修改指令优先于冲突的旧控制项，例如保留眼镜→去掉眼镜。
- [x] 生成过程中能看到单个结果位置及状态，旧双图记录仍可查看。
- [x] 最终图不能来自其他订单、未完成任务或已作废图片。
- [x] 下载不自动标记完成；无最终图不能完成。
- [x] 有未结束任务时不能完成或关闭订单。
- [x] 修改操作数、成功修改数、远端尝试数分别统计。
- [x] 费用未知时显示“未知/未配置”，不显示零元。
- [x] 中文客户名、备注、指令、文件名和控制台输出正常。

## 5. 风格与真实接口验收

阶段 3 已真实验证四图 Base64、单请求单图、2880×2880 以及部分幂等语义，详见历史验收。本阶段没有新真实调用；以下人物/风格与完整供应商条件不能据此视为全通过。先使用模拟响应验证程序逻辑，再使用测试素材进行少量真实联调。以下结果必须实际观察，不能只凭接口返回 HTTP 200 判定通过。

- [ ] 供应商接受所用 Base64 格式，能处理 4 张输入；如不支持，记录差异并调整方案。
- [ ] 新流程一次生成请求返回一张独立图片，不新增候选图调用。
- [ ] 1:1 输出实际比例正确，记录真实像素尺寸，与文档不一致时如实反馈。
- [ ] 提供一组固定测试素材，人工检查大头小肩膀、半身、白底、蜡笔颗粒感、柔和配色和明显腮红。
- [ ] 人工检查主照片人物与发型、眼镜、服装来源规则是否被合理保留。
- [ ] 修改保持原图主要风格，目标变化生效，不随意换人或改构图。
- [ ] 验证实际 task 状态、结果结构和幂等行为，记录文档未覆盖的差异。

风格一致性与人物相似度由商家验收，不承诺固定提示词就能保证每次通过。

## 6. 验收记录方式

每次验收记录日期、代码版本或文件快照标识、测试方式、相关任务组 ID、通过/失败、问题及复验结果。真实调用记录输入数量、耗时、结果数量及可取得的费用依据，不将密钥写入记录。

先完成核心流程和异常恢复，再进行 10～20 笔真实或模拟订单试用。发现问题后先补可复现测试，再修复并复验相关场景。
