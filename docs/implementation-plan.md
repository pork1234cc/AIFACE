## 3. 本计划采用的实现选择

以下是实施建议，不声称已由用户逐项确认；后续没有业务变化时可据此落地。

1. Next.js + FastAPI + SQLite + 本地图片存储，先在单台电脑使用。
2. 独立 Worker + 数据库轮询，不引入 Redis 或 Celery。
3. 新生成及修改均为一个单图子任务；旧双图任务保留兼容。
4. 图片上限同时约束当前订单素材和单次实际模型输入。风格示例、修改基础图也占模型输入额度。
5. 基础风格用配置和提示词固定，不自动附加风格示例图。
6. 一个订单同时只处理一组生成任务；历史记录和已成功图片保留。
7. 每单唯一当前交付图，导出与标记完成分开。
8. 首版不物理删除图片；输入素材移出当前集合、结果作废均保留原文件和历史引用。
9. 修改轮次按新修改任务组计数，失败补生成单独记录调用次数。
10. 已完成和已关闭订单首版只读；暂不增加重新打开流程。

## 6. 每阶段的执行纪律

- 先读对应设计，再按模块拆成不超过 3 个文件的小批次实施；不把全部前后端一次写完再检查。
- 修改模块后运行适用的 lint 和受影响测试；纯文档阶段只验证文档，不运行无关代码测试。
- 修复 Bug 时先写可重现问题的测试；边界、外部请求和状态流转使用有意义的测试。
- 所有 Python 命令使用选定的项目虚拟环境；不跨项目复用环境。
- 业务或接口发生变化时同步更新这套文档和变更记录。
- 当前目录不是 Git 仓库；本次不初始化、不提交。后续是否采用 Git 按开发任务安排。
- 删除文件、物理清理和不可恢复操作不属于默认步骤，须按用户全局规则另行确认。

## 7. 关键决策与易错点

- 模型接口文档实际是 `image2.md`，`头像.MD` 是产品方案。
- 新流程首次只调用一次生成；历史双图记录不能自动选其中一张，也不能为新流程多调用一次模型。
- 1:1 文档尺寸为 2880×2880，模型名称中的 4k 不等于正方形 4096×4096。
- 不把“调用超时”当作“没有扣费、没有受理”。
- 修改基础图也占输入额度，不能在 4 张原素材之外自动再加一张。
- 修改数量固定为 1；修改次数无硬上限，但不代表自动无限重试。
- 费用未知为空，不是零。
