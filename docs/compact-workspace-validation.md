## 2026-09-21 标签同行与修改任务 HTTP 413

纠正记录：此前把“客户名称与订单备注在一行”误解为两个字段并排、标签仍在输入框上方。实际要求是每个标签紧贴输入框，整行呈“客户：[输入框] 订单备注：[输入框]”。已调整订单信息区，Chrome 宽屏和 390px 复核标签与输入框均同行，移动视口无横向溢出。

真实修改任务 `de127e46-adb0-4084-99e4-376cb4ab3429` 的首次提交被供应商以 HTTP 413 明确拒绝。只读检查发现底图为 2880×2880 PNG、17,349,383 字节，连同三张素材经 Base64 后图片部分约 23.8 MB。供应商适配层现只压缩提交副本，保留原尺寸和原始资产；使用该任务输入在本地测得内联图片约 4.5 MB。新增回归测试先复现超大请求体，再验证压缩后请求体、尺寸和源图不变；后端全量测试、Ruff，以及前端 59 项测试、ESLint 和 TypeScript 检查通过。

补生成仅调用一次 `POST /batches/{batch_id}/retry`，生成第 2 次尝试；真实供应商生成 POST 计 1 次。供应商已受理，远端任务编号 `3b39fb9f-e17b-4674-9f92-c9293d6aeb14`；任务最终成功并落盘一张 2880×2880 新图，资产编号 `f1c2361f-6047-44f2-98ac-9f97e54b0766`。订单状态为 `review`。客户端 4.5 MB 图片目标是保守控制值，不是供应商公布的限制。
