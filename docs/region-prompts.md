# 区域提示词编辑器

日期：2026-09-26。当前源码版已接入 Codex 动态对象树与 MobileSAM 独立蒙版，支持颗粒化点选、放大、父级切换和修正。使用、子进程调用、接口及验收见 [Codex 元素拆解](codex-elements.md)。下方 BiSeNet 和待实施记录为历史阶段，当前状态以该文档为准。

## 已确认范围

用户所说的分层是提示词与照片部位的对应关系，不是完整图层编辑器，也不承诺蒙版限定生成范围。保留现有完整提示词、固定素材编号、风格和连续修改流程。小程序仍为独立规划，本次修改现有网页工作台。

## 实施阶段

下方 BiSeNet 阶段为现有实现；后续升级以“颗粒化对象识别与点选”为目标，尚未实施。

1. 本地 BiSeNet ONNX 人像解析、区域配置校验和服务端提示词组装。
2. 照片点击选区、区域列表、逐区要求/素材/保留要求，支持自定义区域与草稿恢复。
3. 接口与前端回归、真实本地推理、构建检查及文档记录。

## 颗粒化对象识别与点选（2026-09-26 确认目标，待实施）

用户进一步明确：主照片需要按实际可见内容颗粒化拆解，鼠标点击时准确选中对应元素，再为该元素填写修改要求。动态命名、对象实例区分和轮廓点选必须一起实现，不能仅更换固定区域名称或用矩形框替代精确选区。

### 识别与数据

- 视觉理解阶段生成动态对象树：对象、部件、细节；同类元素分别拥有实例 ID 和所属对象 ID，例如两个不同人物的头发、同一帽子上的上下两个蝴蝶结。
- 名称、位置描述、层级来自图片内容，不设置固定人像类别表。只描述可见内容；遮挡部分不推测成已识别区域，无法确定的物件用位置和外观描述。
- 视觉模型提供定位线索，分割模型生成每个可选元素的可见区域蒙版。文字描述或定位框不能作为精确蒙版使用。
- 每个对象保存独立蒙版及父子关系，允许整个人物与所属细节的选区包含关系；现有单张互斥索引图不能独自表达全部层级。
- 识别结果绑定底图资产、内容摘要和识别版本；重新识别保留用户已写要求，不能将旧实例要求凭名称自动绑定到新实例。
- 候选对象树与用户已编辑的要求列表分开。现有最多 20 项是已保存区域要求的限制，不能作为识别对象总数上限；最终编辑容量随新协议统一设计。

### 点选交互

- 鼠标悬停预览轮廓与名称，点击后固定选中并显示该元素的修改表单；照片点选和对象树选择同步。
- 默认优先命中当前位置最具体、有效的子元素；重叠或层级歧义提供候选切换和选择父对象入口，不能只凭面积最小就选中噪声碎片。
- 支持放大查看小元素，坐标统一映射到原图；保持原图比例，验证缩放、留白和设备像素比下的点选对齐。
- 自动选区不准确时允许添加包含点和排除点修正，再次分割后更新轮廓；没有可靠蒙版的候选仅允许从列表选择，并明确尚未定位，不能伪装成准确点选。
- 选中的对象名称、所属对象与空间描述共同参与现有区域提示词组装。准确点选本身不表示生成模型会逐像素锁定选区；是否接入生图 mask 是独立能力，不擅自改变现有生成协议。

### 分步实施与验收

1. 核实视觉识别接口、模型及分割运行条件，用用户样图验证对象清单和独立蒙版，再确定模型接入。
2. 实现对象树、蒙版存储和识别接口，覆盖无对象、重叠对象、错误输出、重复识别及底图切换。
3. 实现缩放、轮廓高亮、细节优先点选、父子切换与选区修正，保持修改要求和素材绑定。
4. 以用户的双人插画进行实际验收：两个人的头发分别可选；女生上下两个蝴蝶结分别可选；左右兔子、顶部爱心独立可选；点击对象间空白不误选人物；小元素放大后仍坐标一致。另覆盖清晰人像和非人像图片，避免退化成固定人物分类。

当前接入信息缺口：仓库 `image2.md` 仅说明生图、编辑和任务查询接口；未提供视觉理解接口或可用识别模型。外部视觉模型的配置方式待明确，分割模型选型需验证本机运行及样图效果。本节是目标和拟定方案，不是完成记录。

- 当前会话内置 imagegen 工具提供生成/编辑图片的调用能力，没有向本项目暴露对象树/坐标/蒙版识别服务端点，不能直接打包成应用运行时的内置识别后端。

## 设计

- 自动识别适用于清晰人像，提供头发、眼睛、眉毛、嘴唇、面部皮肤、鼻子、耳朵、服饰、配饰和背景等候选区域；未检测到的区域不伪装成识别结果。衣服仅提供整体类别，不声称识别上衣/下装。
- 模型只在本机推理，安装时下载公开权重；识别请求不下载模型、不调用生图供应商。模型不可用时显示原因，仍可手动添加区域。
- 区域蒙版只用于界面选中/高亮，不进入生图输入；实际提交自然语言目标、逐区指令及真实素材编号映射。识别只是建议，目标描述允许用户修正，多人需补充人物位置。
- 配置新增 region_asset_id 和 region_prompts；区域要求绑定实际编辑底图。底图变化后保留旧要求供核对，但禁止旧区域直接用于新图；用户明确沿用文字或清空后再编辑。
- 区域保存稳定 id、名称、目标描述、来源（识别/手动）、素材资产 ID、修改要求及保留要求。空要求不自动改变内容；选择素材后必须填写用途。失效素材不按编号自动替换，必须重新选择。
- 新字段跟随 params_json 和任务配置快照保存，无数据库迁移。保留旧 changes/material_slots 协议，区域要求独立组装，不转换成重复文字。
- 继续修改从新底图开始，清空上轮区域要求；换图与异步识别不能覆盖用户的文字草稿。

## 本地安装与使用

使用项目根目录 `.venv`，安装锁定依赖后安装模型：

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
.\.venv\Scripts\python.exe scripts/install-region-model.py
```

模型来源为下方作者仓库的 `weights/resnet18.onnx` Release，约 51 MiB，固定 SHA256：`0d9bd318e46987c3bdbfacae9e2c0f461cae1c6ac6ea6d43bbe541a91727e33f`。安装脚本验证完整性，已有文件不覆盖；正常识别无需联网。模型依赖与项目 Python 环境一起安装；无需 CUDA。部署到其他电脑时也需执行安装步骤。

订单中上传主照片后，在“区域提示词”选择区域或直接点击预览照片。填写修改要求、选参考素材、填写保留要求；整体描述仍使用完整提示词。保存后生成，或先点击“预览组合提示词”检查对应关系。识别遗漏时可手动输入区域名称。

重新识别只刷新候选，不覆盖已填写内容。替换底图时可核对并沿用文字，也可清空区域要求。移出或替换被引用素材后，需要解除失效引用并重新选择；不会把新图片偷偷套用原说明。
