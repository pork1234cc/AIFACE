# AIFACE 头像小程序产品与 UI 方案

日期：2026-09-24。状态：规划建议，尚未实施。用户已确认优先开发微信小程序。

## 1. 目标与范围

已明确：项目转向微信头像小程序；提供用户登录注册；新用户免费生成 3 个头像，之后充值；专注不同风格的头像。首版同时包含“主照片生成”和“参考图编辑”两种模式。

建议定位：上传一张自己的照片，获得不同风格、适合社交平台使用的个人头像。

首版建议：单人照片、一次一张、1:1 构图、统一输出规格；上线 6～8 种经过验证的风格。候选为柔彩蜡笔、日系动漫、简约线稿、黏土公仔、复古漫画、国风水墨、清新水彩、商务插画。候选风格不代表现已实现或通过效果验收。

暂缓：多人/情侣/宠物、任意比例、社区、订阅会员、邀请奖励。参考图元素提取、对应修改说明和局部编辑属于首版范围。经营后台继续支持风格维护和故障处理，消费者端保持简单。

### 两种创作模式（用户已确认）

| 模式 | 输入 | 操作与结果 |
| --- | --- | --- |
| 主照片生成 | 一张主照片＋所选风格 | 以主照片为基础生成头像，不要求上传参考图 |
| 参考图编辑 | 一张主照片＋参考图＋编辑说明＋风格选择 | 指定从哪张参考图提取哪些元素、应用到主照片的哪个位置；尽量保留未指定修改的内容 |

参考图编辑示例：“把参考图 1 的帽子戴到主照片人物头上，保留人物五官、发型和原背景。”多图示例：“参考图 1 提取服装，参考图 2 提取背景中的花朵；只改变衣服和背景装饰。”

主照片始终是人物身份和基础画面的依据；参考图只提供明确指定的元素，不默认替换参考图人物的脸、姿势或整张背景。两种模式都必须选择风格；风格决定最终画面表现，编辑说明决定提取和修改哪些元素，两者同时生效。参考图编辑不默认“保持主图风格”，不将风格设为可选项。尽量保留未指定修改的人物身份、构图和内容，但这些内容的绘画表现随所选风格统一转换。

参考图按“参考图 1、参考图 2……”稳定编号，每张图旁填写“提取什么、改到哪里”，支持继续添加；数量和大小上限依据模型能力与成本验证后配置，本次不擅自限定为只能一张。未写清用途、引用失效或缺少参考图时先提示，不提交付费生成。

首版采用图片＋文字指令完成元素提取与融合，选区涂抹工具不作为已确认需求。不承诺逐像素保留，也不把模型编辑表述为精确抠图；未修改区域、人物相似度及元素融合必须实图验收。

## 2. 用户流程与登录

游客浏览风格/选择模式 → 点击制作 → 登录/自动注册 → 领取新人 3 次 → 上传主照片 → 参考图编辑模式补充参考图和编辑说明 → 确认风格 → 提交生成 → 查看作品 → 保存或继续创作。

- 首页可浏览，不强迫首次打开即登录。
- 用户主动点击“登录并领取 3 次”后建立业务账号；已有账号正常登录，不重复注册。
- 技术方案为微信登录凭证由服务端验证后关联平台身份，再签发本系统会话；昵称和头像单独设置，不假设登录会自动取得资料。
- 首版建议不要求密码，不强制绑定手机号；后续确有业务用途再增加。
- 登录入口展示用户协议与隐私政策；照片上传前明确用途与存储方式，不默认同意。
- 登录过期保留当前风格和编辑状态，重新登录后继续，不自动发起生成。

## 3. 免费次数与计费规则（建议值，开发前定稿）

| 场景 | 建议规则 |
| --- | --- |
| 新人赠送 | 同一平台业务账号仅赠送 3 次，清缓存/重新登录不重送 |
| 生成单位 | 成功交付 1 张头像消耗 1 次；每次请求仅生成 1 张 |
| 双模式额度 | 建议两种模式共用新人 3 次与购买次数，不各赠送 3 次；均按成功交付 1 张扣 1 次，最终售价分别测算两种模式成本后确定 |
| 免费体验 | 与付费使用同档质量，可下载完整图片；按适用规则保留 AI 标识 |
| 扣减时点 | 提交先冻结 1 次，图片成功保存、审核通过并可交付后才核销 |
| 失败 | 明确失败解除冻结；不消耗用户次数 |
| 状态不明 | 后台核对原任务，不直接重新调用模型；达到服务承诺期限后可补回用户次数，成本由平台承担 |
| 重新生成 | 用户主动再次生成视为新任务，再消耗 1 次，按钮提前标明 |
| 下载与恢复 | 重复下载、恢复原任务下载不扣次 |
| 扣次顺序 | 优先免费次数，再扣购买次数；账本保留来源 |
| 有效期 | 首版建议不设有效期；如后续调整须事先明确展示，不追溯缩短已购权益 |
| 并发 | 首版每账号最多 1 个运行中任务，所有次数变化由服务端事务控制 |

“每个账号一次”不能保证“每个自然人一次”。采用账号、请求速率和异常行为联合限流；同 IP 不直接视为同一用户。设置运营侧每日赠送成本预警和总成本预算，避免开放赠送后费用失控。

## 4. 充值与成本

用户界面使用“购买生成次数”，不设置可提现人民币钱包。首版可规划 10 次、30 次、60 次三个套餐，不同时引入钻石、积分和会员等级。

价格暂不确定。需分别实测两种模式及不同参考图数量下的实际平均成本、失败率和平均出图时长。当前文档中的模型费用可能为空，不能当作零成本；本次规划未调用付费模型。

定价模型：套餐收入 ×（1 − 实际渠道费率）− 套餐张数 × 单张平均交付成本 − 赠送成本分摊 − 退款及运营分摊。单张交付成本应包含失败调用、必要重试、审核、存储和流量。若 1000 个新用户全部用满免费额度，仅赠送生图成本就约为 3000 × 单张平均交付成本。

充值页面：剩余次数、套餐次数/总价/单张折算、有效期、失败规则、退款说明、购买按钮、订单记录。不得通过默认勾选或自动续费制造额外购买。

支付成功以服务端验证后的支付通知/主动查单为依据，到账操作幂等；客户端成功提示不能直接加次数。覆盖支付取消、回调延迟、重复通知、乱序通知、退款和对账。支付成功返回原生成页并保留模式、主照片、参考图、编辑说明和风格，但由用户再次点击生成。

购买次数可能涉及虚拟支付类目；必须按实际经营主体、平台类目和终端能力核实支付通道。不能因为名称叫“次数包”就视为普通实物支付。iOS/安卓分别验证，不设计违规站外绕行。微信虚拟支付规范页本次未能直接读取，通道、费率、终端版本与资质不视为已核实。

## 5. UI 信息架构

底部仅三个入口：做头像 / 我的作品 / 我的。充值通过剩余次数卡片和额度不足弹层进入。

| 页面 | 主要内容与操作 |
| --- | --- |
| 做头像 | 小标题“换个头像，换种心情”；“主照片生成 / 参考图编辑”模式切换；新人 3 次提示或剩余次数；风格入口 |
| 风格详情 | 示例大图与圆形裁切预览、适用照片说明、“用这个风格” |
| 登录 | 简洁半屏，登录并领取 3 次，协议与隐私入口，不展示密码表单 |
| 制作·主照片生成 | 模式切换；上传主照片；预览和替换；当前风格；底部“生成头像 · 使用 1 次” |
| 制作·参考图编辑 | 模式切换；主照片区；按编号排列的参考图和各自编辑说明；继续添加参考图；必选风格；底部“生成编辑后的头像 · 使用 1 次” |
| 生成中 | 排队/制作/保存等真实阶段；退出后可在作品页查看，不使用虚假百分比 |
| 结果 | 方形大图、圆形预览、“保存头像”主按钮、“换个风格”次按钮 |
| 我的作品 | 两列作品；进行中、成功、失败状态；点击查看；空态引导首次生成 |
| 我的 | 用户资料、免费与已购次数、购买入口、购买记录、帮助反馈、隐私和账号注销 |
| 购买次数 | 三档套餐、支付与退款说明；到账后返回原流程 |

设计方向：简洁头像画廊。暖白背景 #F7F8F5、深色正文 #202724、松绿色主按钮 #24694F，卡片圆角 16px；头像效果本身提供色彩。备选为浅紫强调色，不采用后台侧边栏和密集表格。

采用 375px 手机逻辑宽度设计，同时覆盖 320～430px；左右边距 16px、卡片间距 12px；标题 22～26px、正文 14～16px、辅助信息至少 12px，触控区域至少 44px。预留微信胶囊、安全区及底部导航空间。

首页首先显示风格与效果，不用大幅营销横幅占据首屏。风格样张统一输入人物、构图和尺寸，便于比较差异；示例不是用户生成结果，明确标注。正式展示必须用实际生产模型验证样张，现有部分封面仅为风格示意，不能直接承诺效果。

两种模式共用底部导航，不增加第四个入口。模式切换保留主照片；参考图和说明在主照片模式中隐藏并保留草稿，但不发送给模型、不参与该模式的生成。参考图模式将“主照片”和“参考图”分区，避免用户误认为两张图同等决定人物身份。新选风格不清空已填写的编辑说明。

关键状态：剩余 0 次时展示购买入口并保留照片；无网络时允许重新查询原任务；上传不符合要求时说明原因；审核未通过不扣次；保存权限被拒绝时提供操作指引，保留结果；照片和生成结果默认私有。

## 6. 现有项目如何改造

依据 README.md、docs/architecture.md、docs/data-model.md：目前为 Next.js/React + FastAPI + SQLAlchemy/SQLite + 独立 Worker，已具备单图生成、风格快照、历史版本、幂等、查询与下载恢复。商家客户订单不能直接当作消费者账号或支付订单。

推荐保留 FastAPI、供应商适配与任务恢复能力，新建小程序客户端；现有网页改为经营后台。小程序建议 Taro + React + TypeScript，沿用团队 React 技术经验，但 Next.js 页面、DOM、路由和样式不能直接搬入，需按小程序规范重做。独立管理依赖，不直接照搬现有 React 版本。

新增账号、额度账本、商品套餐、支付订单、用户资产隔离、内容审核、经营后台权限与审计。服务端确定模型、风格模板与规格，不接受客户端任意控制模型、价格或余额。

复用现有主图/素材编号、素材用途说明与提示词组装能力，两种 UI 模式共用生成服务。请求与任务快照增加明确模式：主照片模式仅提交主图和风格；参考图模式提交主图、有序参考图与逐图用途及风格。两种模式均必须传入有效风格编号，未选风格不得生成，不能回退为原图风格。服务端复验模式对应的必填项、资产归属和引用关系，模式切换不能造成隐藏素材误参与生成。编辑说明用于用户指定的元素修改，后台模型配置仍不对消费者开放。

建议数据实体：users、platform_identities、credit_accounts、credit_ledger、credit_reservations、products、payment_orders、payment_events、refunds；生成任务和素材增加明确的用户归属。赠送、扣次、返还、补偿各有唯一业务编号；充值订单和生成任务分别管理，能互相追溯。

所有作品、图片下载和任务查询都核验当前用户归属；经营后台独立鉴权。模型密钥、支付凭据仅在服务端。照片不使用永久公开链接，采用私有对象存储和短期授权访问。

正式运营建议 PostgreSQL + 私有对象存储；Worker 首版可继续使用数据库任务队列，需求明确后再加入 Redis 等组件。现有 SQLite 可用于原型验证；不能在未经并发和故障测试时直接承诺生产支付可靠性。

用户 API 使用独立 HTTPS 入口，生产部署在持续运行的云服务。现有本机 + Cloudflare Access 邮箱验证入口保留给内部使用，不直接作为小程序用户的身份验证方案。

## 7. 实施阶段与验收

1. 产品和效果验证：确认平台/主体/类目，确定免费次数与套餐规则；以获得使用授权的不同人像验证 6～8 个候选风格，记录相似度、构图、失败率、成本和耗时；输出最终样张和价格表。
2. 核心体验：小程序登录、双模式上传与编辑说明、选风格、异步生成、作品、保存；贯通赠送/冻结/核销/返还。验收重登不重送、并发不超扣、生成退出不丢失、用户之间不可访问图片；额外验证单图模式不混入参考图、编辑模式无参考图/无说明不可提交、多参考图用途准确对应、修改外区域尽量保留及模式切换草稿恢复。
3. 付费闭环：套餐、平台支付、到账、退款、补单、后台配置。验收重复通知只到账一次、支付取消不加次、回调延迟可恢复、退款和余额一致。
4. 上线准备：域名与平台配置、经营所需资质/备案核实、隐私与照片处理规则、输入输出审核、AI 生成标识、故障告警、备份恢复、真机和弱网测试、灰度发布。此列表为待核实工作，不构成已经满足法律或平台要求的结论。

新增参考图编辑后，单图版本的 3～5 周估算不再作为双模式版本承诺；需完成多图编辑效果、移动端交互和两种模式成本验证后重新排期。

运营关注：登录到首次生成转化、三次体验完成率、首次付费转化、付费用户复购、各风格成功率、平均等待时间及每位用户毛利。暂不引入无关社区指标。
