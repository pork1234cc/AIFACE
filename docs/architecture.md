# 项目架构与目录规划

更新日期：2026-09-21。阶段 5 已实现单图生成、修改自动更新、版本切换和交付闭环；真实人物及修改效果仍待阶段 6。

## 1. 依据与范围

- 产品依据：`../头像.MD`。
- 模型接口依据：`../image2.md`；阶段 3 已验证远端协议，效果和计费仍有待核实。
- 用户已确认：输入图片最多 4 张；首次生成 1 张直接交付，修改成功自动替换，旧版本保留可切回。
- 用户已确认：只记录修改轮次，由商家控制，不设置系统硬上限；每次修改均由商家手动发起。
- 首版面向单商家内部使用，只内置 `q_crayon_001` 风格。
- 覆盖订单、素材整理、生成、修改、版本切换和交付。
- 多商家、支付、客户自助、小红书消息接入和局部重绘编辑器不属于首版。

## 2. 技术方案

| 层次 | 计划选型 | 职责 |
| --- | --- | --- |
| 前端 | Next.js、TypeScript、Tailwind CSS | 工作台与任务进度展示 |
| 后端 | FastAPI、SQLAlchemy、Alembic | 参数校验、业务处理、数据持久化 |
| 数据库 | SQLite | 首版本机运行的数据存储 |
| 文件 | 本地文件系统 | 素材、模型输出、交付文件 |
| 后台任务 | 独立 Python Worker、数据库轮询 | 提交远端任务、查询结果、保存图片 |
| 模型适配 | 自有 HTTP 适配层 | 按项目提供的接口文档发送请求 |

首版按单台电脑本地运行规划，监听本机地址。公开部署和多用户访问另行设计。前端通过同源 `/api` 路径访问后端，密钥仅由后端和 Worker 读取。

`api` 处理协议及校验，`services` 承载业务，`providers` 封装供应商协议。不额外建立没有实际需要的通用仓储层或插件框架。

本地 Python 环境为项目根目录 `.venv`，使用 Python 3.12.14，未继承全局 site-packages。后续在项目根目录通过 `.\.venv\Scripts\python.exe` 运行 Python、pip 和测试；无需依赖跨终端的激活状态。已验证解释器路径、环境隔离和 UTF-8 中文输出。PowerShell 向 Python 管道传入中文脚本时，须先将 `$OutputEncoding` 设为 `[System.Text.UTF8Encoding]::new($false)`，仅设置 Python 输出编码无法修复输入编码损坏。

本机使用 Node.js 22.23.2、npm 10.9.8，前端安装 Next.js 16.3.5、React 19.3.0、Tailwind CSS 4.3.3，以 `package-lock.json` 固定依赖。后端依赖声明见 `backend/pyproject.toml`，安装快照见 `backend/requirements.lock.txt`。`.gitignore` 已排除本地密钥、虚拟环境、缓存、构建产物和运行数据；当前尚未初始化 Git 仓库。

阶段 1 实现约定：

- `app.main:create_app` 为 Uvicorn 工厂入口，lifespan 管理数据库引擎释放；测试通过注入配置隔离数据库。
- 配置从根目录 UTF-8 `.env` 和进程环境读取。密钥字段不参与对象展示或序列化，缺失不阻止基础工程启动；实际模型调用前必须执行 `require_image_api()`。
- SQLite 默认位于 `storage/database/aiface.sqlite3`，启用外键、WAL、5 秒锁等待；数据库相对路径始终基于项目根目录。
- Alembic `0001_baseline` 仅建立版本基线，无业务表。启动脚本显式迁移，健康检查验证版本与当前迁移 head 一致。
- 前端固定将同源 `/api` 转发到 `127.0.0.1:8000/api`，无跨域和前端密钥配置；首页显示连接状态，失败可手动重试。
- API 提供关联 ID 和脱敏错误；不输出原始校验输入或异常文本。首页插画是 CSS 示意图，不代表供应商输出。
- `start-dev.ps1` 仅监听本机，端口冲突时终止启动；Ctrl+C 停止自身进程树。`check.ps1` 执行 lint、格式、测试、类型检查，可选生产构建。

Windows PowerShell 5.1 的中文脚本需保存为 UTF-8 BOM；否则解析器可能按 ANSI 解码并报语法错误。ESLint 暂锁定 9.39.5，原因是 Next.js 携带的 React 插件在 ESLint 10 下不能运行；待上游兼容后再升级。详细启动与恢复方式见 `../README.md`。

## 4. 图片与风格规则

1. 每单上传的当前输入素材合计最多 4 张，其中恰好一张主照片，参考图最多一张，其余为辅助照片。
2. 任一次发送给模型的图片也不得超过 4 张，风格参考图和修改基础图均计入。
3. 内置风格主要通过配置和提示词表达；风格示例图不自动加入请求。确需发送时，必须明确选入并占用额度。
4. 修改请求必须包含基础结果图；如需补充其他图片，在剩余 3 个名额内明确选择，不能自动把原来的 4 张素材全部附加。
5. 不因超过额度静默丢弃图片。前后端均校验数量、图片归属和角色。
6. 发型和服装来源引用图片 ID；未上传参考图时，不允许选择“跟参考图”。
7. 首版固定白底、1:1。按模型文档，1:1 对应 2880×2880，不能将其表述为 4096×4096 输出。

以上输入组合是规划规则，进入实现前与数据/API 文档保持一致。

阶段 2 实现细节：素材读写经受控 API，图片通过 Pillow 验证真实格式、完整解码、像素上限和静态单帧；python-multipart 解析上传。配置 `AIFACE_STORAGE_PATH` 可隔离素材根目录，数据库仍由 `AIFACE_DATABASE_PATH` 单独配置。临时文件写入后 fsync、原子重命名，异常中间文件保留，不自动清理。

所有订单写操作使用 SQLite `BEGIN IMMEDIATE`，在写锁内检查当前上限；数据库唯一索引和数量触发器进一步兜底。读取列表不逐单查询素材，详情一次查询所属资产。

前端 `/orders`、`/orders/new`、`/orders/[id]` 使用同源 JSON/multipart API。表单有错误、忙碌与未保存提示，来源参数未保存时先保存或撤销再操作素材。终态界面只读；已接通单张生成、修改、交付与恢复表单。

隔离验收支持服务端环境变量 `AIFACE_BACKEND_ORIGIN`（默认 `http://127.0.0.1:8000`）与 `AIFACE_NEXT_DIST_DIR`（默认 `.next`）。额外构建目录必须留在 frontend 内，并以 `.next-` 为前缀以纳入忽略规则。Next.js 转发缓冲 22 MiB，容纳 20 MiB 图片及表单开销。风格配置按固定白名单加载，不读取请求传入路径，不自动添加参考图。

## 5. 模型适配

- Base URL：`https://ai.apii.cn`。
- 文档模型名称：`gpt-image-2.0-4k`。
- 密钥读取：项目 `.env` 中已有的 `image_api`；不复制到文档、前端或日志。
- 首次生成使用 `/v1/images/edits`，提交本人素材及提示词；修改同样使用该接口。
- 使用 `async: true`，保存返回的 `task_id`，通过 `/v1/tasks/{task_id}` 查询。
- 本地素材计划以 Base64 发送，输出优先使用 URL 并及时落盘。
- 原始文档未列出 `n` 等批量数量参数，不自行添加。首次生成和修改均只创建一个单图任务；旧双图任务的恢复沿用原目标。
- 每个请求只描述一张独立头像，不通过额外调用增加候选图。
- 若响应数量与预期不符，作为接口差异记录并处理，不把拼图当作要求的一张独立头像。
- `Idempotency-Key` 在文档示例中出现，但有效期、冲突行为和重放语义尚未说明，需要集成验证。

## 6. 执行与恢复

阶段 3 已落地：`app/models/orders.py` 保存业务模型；`schemas/generation.py`、`services/generation.py`、`api/generation.py` 实现快照和恢复协议；`providers/apii.py` 使用 httpx；`app/worker.py` 为独立进程入口。前端 `generation-panel.tsx` 展示任务、图片、历史和核对表单，每 4 秒顺序轮询，卸载取消请求；sessionStorage 保留未确认操作的原始正文和幂等键，刷新后可重发原请求。

运行 `python -m app.worker`；启动脚本正常模式同时启动 Worker，SmokeTest 模式不启动付费任务处理。首版单 Worker，每个数据库有操作系统进程锁；查询默认 5 秒，连续错误按指数退避到最多 300 秒。协议异常继续保留远端编号查询，不擅自猜测终态。

下载只接受 HTTPS、443 端口，不附模型鉴权、不自动跟随重定向，并复用 20 MiB/4000 万像素图片校验。真实联调发现本机代理把供应商 CDN `img.ksidc.icu` 解析到 198.18/15；仅对此精确域名允许该伪 IP 网段，其余域名仍需公网地址，127.0.0.1/私网仍拒绝。不要扩大为任意域名或任意私网地址。URL 仅在任务待下载阶段存数据库，成功后替换为图片尺寸元数据，不出现在 API 和普通日志。

前端创建任务组后立即获得本地任务组 ID。Worker 从数据库领取任务，提交远端请求并定期查询。模型生成成功后，先完成图片下载与有效性检查，再记录本地任务成功。

首版只运行一个 Worker。领取任务时使用条件更新及短事务，避免重复领取；HTTP 请求期间不占用数据库写事务。

- 新操作只创建一个任务位置；历史双图任务各自保存状态，兼容部分成功恢复。
- 已保存远端任务 ID 的任务在重启后继续查询，不重新提交。
- 远端成功但下载失败时，重试下载，不重新生成。
- 提交请求超时且未获得远端 ID 时，记为 `submission_unknown`，暂停自动重发；需要核对供应商任务或明确确认重新生成。
- 只读状态查询可退避重试；不能用同一规则盲目重试付费生成请求。
- 错误信息脱敏，记录请求关联 ID，不记录密钥和完整 Base64 图片。

## 7. 交付事务与下载

services/deliveries.py 与 api/deliveries.py 管理当前交付、历史切换、下载及终态。Worker 在成功资产提交事务内自动设置当前交付；唯一索引兜底每单一张。修改失败不触碰原交付记录。

前端 delivery-panel.tsx 展示当前图和版本历史；generation-panel.tsx 保留任务与恢复入口。下载读取最多 20 MiB 的图片字节并核验完整性，在短事务复验选择未改变后记录导出时间；不创建 ZIP 或额外模型任务。完成/关闭由独立确认操作触发，终态仍可下载。

## 8. 已知限制

四张 Base64 输入、两个独立异步编辑任务、每任务单图及 2880×2880 PNG 已真实验证。同键重放返回原编号，同键改正文也返回原编号；幂等有效期、并发上限及计费尚未知。专用程序绘图不等同真人一致性验收；测试图出现原素材没有的眼镜，风格/人物细节仍需阶段 6 人工效果验收。

文档没有提供价格或用量字段。首版记录请求、成功失败和耗时，费用未知时保存为空，不能显示为零元或虚构估价。
