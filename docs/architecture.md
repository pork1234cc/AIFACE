# 统一创作架构

更新：2026-09-21。实施依据为 [AIFACE_PLAN.md](../AIFACE_PLAN.md) 最新方案，历史阶段记录不再作为当前协议。

## 业务边界

每次以一张明确选定的底图创作。首次为上传主照片，继续修改为当前交付图。风格控制表现方式，素材仅提供用户填写的提示词指定的元素，未指定修改的内容默认保留。支持多人、物品及版式，不预设白底、半身、单人或固定取景。每次只生成一张图片。

订单上传一张 main 主照片和任意数量的 material 素材图。模型输入为底图加配置中非空位置的素材，按位置顺序发送，提示词明确编号映射与用途；风格封面不会发送。历史结构化配置仍按修改项引用顺序去重。供应商提交副本有内联图片总量目标，超过时先压缩，仍过大则明确报错。

## 分层

Next.js / React 页面通过同源 `/api` 请求 FastAPI；SQLAlchemy + SQLite 保存状态，独立 Worker 轮询任务，ApiiProvider 处理供应商协议。当前虚拟环境为根目录 `.venv`，执行 Python、测试及 lint 均使用 `.venv/Scripts/python.exe`。

2026-09-22 模型设置：侧栏新建订单改为普通导航项，新增模型设置页；当前只支持 Apii 图片编辑/任务查询协议。后端将 URL、模型、质量及可选 API Key 原子写入已有 `.env`，读取接口仅返回密钥是否存在。新生成任务和手动风格示意图保存模型、质量、接口地址快照；Worker 每轮重新加载凭据，旧任务查询继续使用其接口地址快照。更换 API Key 可能影响仍在运行的旧任务，应待其完成后操作。单图生成成功已自动选为当前交付图，版本历史以文字显示当前状态，其余版本提供切换按钮。

2026-09-22 模型设置页排版：接口 URL、模型 ID、质量、API Key 均以名称和控件同行显示；标题下不展示协议与新任务生效说明。模型 ID 允许编辑并随新任务快照传给 Apii 的 `model` 参数，默认 `gpt-image-2.0-4k`；实际可用 ID 由供应商决定，本地只校验格式，不在保存时发起真实模型调用。OpenAI 官方 GPT Image 2 的 ID 为 `gpt-image-2`，与当前 Apii 文档的 ID 不同，不能据此推定 Apii 会接受官方 ID。

2026-09-22 导航文案：左侧 `/styles` 入口显示“成图风格”，路径及页面内部名称保持原有语义。

`schemas/orders.py` 定义统一配置；`services/prompts.py` 校验关系并组装提示词；`services/generation.py:preview_creation` 共用底图版本与文件完整性预检，预览和 initial/revision 提交走同一语义。提交在写事务内复验并保存配置、风格、输入摘要和最终提示词快照。预览不调用模型。

`services/revisions.py` 保留版本血缘；修改只能基于当前成功、未作废的交付图。继续修改由前端清空已完成修改项及补充要求，默认保持原图风格；生成失败保留本轮配置和上一张交付图。原始主照片、任务底图及当前交付图分别保留。

## 数据与运行隔离

新默认数据库 `storage/unified/database/aiface.sqlite3`，图片根目录 `storage/unified`。已有 `.env` 无路径覆盖，本次不改密钥。自定义隔离环境仍使用 `AIFACE_DATABASE_PATH` 和 `AIFACE_STORAGE_PATH`，两者必须成对指向新存储。

新增迁移 `0006_unified_creation` 创建 `v2_*` 表；当前 ORM、API 和 Worker 只访问新表，无字段转换或旧任务领取路径。历史迁移保持原样，新库首次启动执行到 head；历史空表可存在但不参与新业务。Alembic 自动比较只包含 `v2_*`，不会建议删除保留表。

旧默认库只读检查发现 2 个 succeeded 任务，无未结束任务。旧数据库、图片、备份均保留，不取消或重放旧任务。当前运行的旧服务需要正常退出后再启动新版本，不能让旧内存进程继续处理新协议。

## 执行与恢复

每库单 Worker 进程锁；每订单仅一个活动任务组。请求体和幂等键在客户端提交前保存，服务端校验相同键正文摘要一致。提交不明不自动重发；远端 ID 已知则继续查询；下载失败仅恢复下载。每个任务快照固定本轮输入、比例和要求。

2026-09-21 订单状态跟随持久化任务组：提交首次生成进入“生成中”，提交修改进入“修改中”；成功保存图片和交付记录后进入“待交付”；明确失败分别回“待整理”或“待交付”，历史错误留在任务尝试中。关闭浏览器不影响 Worker；Worker 重启继续轮询已知远端任务，提交期间中断且远端受理不明时保留原任务等待人工核对。订单列表批量读取每单最新任务组状态，显示失败／待核对提示；可见页面轮询，状态筛选选中即重新查询。旧 ready/revision_requested 状态由 0010 迁移转换，已关闭仍是特殊终态。

成功落盘同事务更新唯一当前交付；历史保留可切回。下载不自动完成订单。完成/关闭为独立确认，终态只读但允许下载。素材移出仅修改活动标记，失效引用保留并明确报错，由用户修正。
